# AGENTS.md — Agent 接入说明（模板）

> **如果你是一个 AI Agent，并且这个仓库已被连到你的工作区：先读完本文件再干活。**
> 目标：让你在 5 分钟内建立正确理解，并在需要改档案时不破坏规矩。

## 1. 这个仓库是什么

这是<所有者>的**跨 Agent 个人档案库**，纯 Markdown + git。
它**不是**任务工作区——具体要干的活在这里没有，这里只有"这个人是谁、怎么和他协作"。
项目文件在<主工作库路径>，本仓库只放跨项目仍成立的事实与约束。

## 2. 五步接入协议（第一次连接时按顺序做）

1. **读本文件**（你已经在这）。
2. **读 `README.md`**，记住目录结构与三条硬规则。
3. **读 `memory/00-index.md`**，然后按你的任务需要，只读相关的 1-3 份 memory 文件。
   - 任何任务都该读：`memory/preferences.md`（协作偏好与交付纪律）。
   - 涉及身份/学历/经历：`memory/identity.md`。
   - 要动文件/要清理/要迁移：`memory/rules.md`（红线，必读）。
4. **读 `routines/00-index.md`**，挑与当前任务匹配的工作流照做。
5. **看一眼 `CHANGELOG.md` 最近 10 行**，知道最近改了什么，别用过时结论。

> **不要**一次性把整个仓库塞进上下文。这份档案是为"按需读取"设计的。

## 3. 怎么读（避免读到过期信息）

| 标记 | 含义 | 你怎么用 |
| --- | --- | --- |
| `E1 已核实` | 有证件/原件/系统记录/独立重算支撑 | 可直接引用 |
| `E2 本地证据` | 有文件、日志、截图，但未独立复核 | 可以，注明来源 |
| `E3 自报` | 本人陈述，日期敏感 | 涉及钱、职业、工时、家庭决策前**先问刷新** |
| `E4 推断` | 多条间接证据推出 | 可作参考，不可当事实陈述 |
| `E5 待确认` | 存在冲突或只有单方说法 | **不得使用**，除非已确认 |
| `E6 已作废` | 曾经的错误说法 | **绝对不要引用**，它是反例 |

档案里每条更正都写成"错误说法 -> 正确事实 -> 谁裁定 -> 什么证据"，
因为要求**可追溯**：不接受悄悄改内容，只接受"改内容 + 留下更正记录"。

## 4. 怎么改（commit 规范）

### 4.1 什么时候该改档案

| 该改 | 不该改 |
| --- | --- |
| 明说"记到档案里 / 记住这个 / 以后都这样" | 一次性任务细节、临时进度 |
| 发现档案事实错误，且**已确认** | 你从对话里"推测"出来的倾向 |
| 一次踩坑后总结出可复用方法 | 已有 commit 覆盖过的旧结论（去看 git log） |

### 4.2 改动允许的范围

- **可以**：`memory/`、`projects/`、`routines/` 下的 `.md`，以及 `CHANGELOG.md` 追加一行。
- **先问再做**：新增顶层目录、改 `AGENTS.md` 本身、改 `README.md` 结构、删除任何文件。
- **禁止**：碰 `.git/`、塞入任何凭据、`git push --force`、改历史 commit。

### 4.2.1 暂存时禁止 `git add -A`

**必须用显式路径**：`git add memory/identity.md CHANGELOG.md`。

原因：`git add -A` 会把意外文件（工具自动生成的临时目录、路径展开失败的产物）
一并入库。改完后**先 `git status --short` 看一眼**再 commit。

### 4.3 commit 格式（强制）

```text
<type>(<scope>): <一句话说明>

<正文：为什么改，证据是什么，谁确认的。可多行。>

Agent: <你的名字>
Confirmed-by: <确认人>
Source: <会话/文件/任务>
```

`type`：`feat`（新增）/ `fix`（更正错误事实，**必须写"旧说法 -> 新事实"**）/ `docs`（措辞结构）/ `chore`（维护）
`scope` = 目录名：`memory` / `projects` / `routines` / `repo`。

### 4.4 回退

```powershell
git log --oneline -20
git show <hash>
git revert <hash>      # 用 revert，不要 reset --hard
```

## 5. 写档案的格式约定

- 文件头写 `> 建档/最近更新：YYYY-MM-DD ｜ 证据等级：E1/E2/...`。
- 一份文件只讲一件事；超过约 200 行就拆分。
- 表格优先于长段落；每条结论尽量带证据来源。
- **不写凭据、不写真实姓名与学号、不写涉密原文、不写完整手机号**——
  确需记录时用脱敏形式。

## 6. 与其它记忆设施的关系

本仓库是**跨 Agent 的档案层**，不取代各 agent 自己的记忆系统：

| 设施 | 关系 |
| --- | --- |
| 本仓库 | **共享档案**：身份 / 偏好 / 工作流，人工可读、可 git 回溯 |
| 各 agent 自己的 memory | **任务记忆**：某个项目干过什么、失败教训，颗粒更细 |
| 共享记忆 MCP | **机器记忆**：键值式，供 agent 程序化读写 |

**避免竞争性副本**：同一事实只在一个地方是权威源。
本仓库是"身份/偏好/工作流"的权威源；项目细节的权威源在工作区自身的
`00_CONTEXT/AGENT.md` 与 `STATUS.md`。
