# 文件操作安全协议

> 用途：动任何**重要目录**、做清理、做迁移前。
> 来源：一次真实误删事故的复盘。**这些规则是被事故教出来的，不是想象出来的。**

## 事故原型

从一个**云同步目录**跨盘 `Move-Item` 一个项目，因文件夹被进程锁定而失败；
随后的清理步骤里写了 `Remove-Item $dst -Recurse -Force`，把可恢复状态破坏了，
云盘随后记录了删除事件。

四个根因：

1. 把同步云盘当成普通本地目录
2. 跨盘迁移用 `Move-Item` 而不是"复制-校验-切换"
3. 在同一脚本里把"复制准备"和"破坏性清理目标"组合在一起
4. 第一条命令失败后没有停，也没有重新核对两端文件数

## 七条硬规则

1. 重要项目 / 云同步目录 / 原始材料 / 原始媒体 / 代码归档 / 大数据集 -> **永不 `Move-Item`**。
2. **永不在迁移、复制或重试脚本里出现 `Remove-Item -Recurse`**。
3. 永不删除已存在的目标目录腾位置；改用带时间戳的新目标 `_copy_YYYYMMDD_HHMMSS`。
4. **永不在同一命令块里组合"删除"与"复制/移动"**。
5. 任何移动/复制**失败后立即停止**，先检查源 / 目标 / 锁 / 同步客户端状态。
6. 经过 OneDrive / Google Drive / Dropbox / 其它同步盘的路径：**先暂停同步客户端**，
   把本地路径当作"同步管理的状态"，不是唯一真相。
7. 不可替代的目录：未获**明确确认副本可用**前，不得归档或删除原目录。

## 安全迁移九步

```text
1. 盘点源：绝对路径、文件数、目录数、总体积、最大文件、mtime
2. 写 manifest 到约定的日志目录
3. 建新的空目标；目标已存在则用时间戳备选名
4. robocopy /L 预演，看清会复制什么
5. 只复制，不移动
6. 核对源与目标的数量和体积
7. 高价值文件校验哈希（或抽样哈希）
8. 源至少保留一个复核周期
9. 只有批准后，才归档或标记源为已迁移（不自动删除源）
```

## 判定"可删"的唯一标准

> **全量内容哈希在别处有等价副本。**

不是目录名、不是名字带 `.bak` / `emptybak`、不是体积、不是"看起来像缓存"。

**真实教训**：一个名字像"空壳备份"的目录，全量哈希核验后发现近三分之一文件在全盘任何位置
都没有副本，且是真实用户资料。按名字猜就全毁了。

## 删除候选必须同时提供

1. **清单**：路径 + 体积 + 文件数
2. **条件**：什么情况下才删
3. **顺序**：先删哪个后删哪个
4. **回滚**：删错了怎么恢复
5. **实测释放空间**：删除前后各读一次可用空间

> 逻辑文件大小不等于释放的物理空间；压缩、链接、云占位、回收站都会让估算失真。

## 失败协议

1. 停止一切写、移动、删除、清理操作。
2. **不要**用破坏性清理重试。
3. 记录精确命令、错误、时间戳、源路径、目标路径。
4. 检查两端是否仍存在，列数量与体积。
5. 涉及云同步文件夹，先停同步客户端再检查。
6. 怀疑已删：先查本地缓存、回收站、云端历史、恢复工具，**再**往该盘写新数据。

## 版本控制相关的坑

| 坑 | 规避 |
| --- | --- |
| `git add -A` 把意外文件打进索引 | **必须用显式路径**；改完先 `git status --short` 看一眼 |
| 目录名含 `%`（路径变量展开失败产物） | 加入 `.gitignore`，并从索引 `git rm --cached` 移除 |
| `.gitignore` 写错前缀（`local/` vs `.local/`） | 写完后用 `git check-ignore -v <真实路径>` **实测**，别只看内容 |
| 敏感内容已进历史 | 未推送时用 `filter-branch` 清洗 + `gc --prune=now`；**已推送则必须轮换凭据** |
| 移动超长路径**静默失败**（不回滚不报错） | 用 `robocopy /E /MOV`（原生支持长路径） |
